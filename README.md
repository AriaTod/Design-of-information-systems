## Design-of-information-systems
Разработка микросервисной архитектуры с GraphQL


Состав команды: Свинин А. Г.; Cуворин И. А.; Андронов Д. А.

# Цель работы
Целью работы является изучение принципов построения микросервисной архитектуры и организации взаимодействия между независимыми сервисами с использованием технологии GraphQL. В рамках работы была разработана распределенная система, состоящая из нескольких независимых микросервисов, объединённых через единый GraphQL API Gateway.

# Используемые технологии
Для реализации проекта использовались следующие технологии:
- JavaScript (Node.js)
- GraphQL
- Apollo Server
- Apollo Gateway
- Apollo Federation
- npm


# Общая архитектура системы
Система построена по микросервисному принципу. Каждый сервис отвечает только за свою область данных и может быть запущен независимо от остальных компонентов.
Архитектура проекта:

'''Frontend (клиент)
↓
GraphQL API Gateway (Apollo Gateway)
↓
Users Service
Products Service
Orders Service

Порты сервисов:
- Gateway — localhost:4000
- Users Service — localhost:4001
- Products Service — localhost:4002
- Orders Service — localhost:4003

Сущность User содержит следующие поля:

- Изменение пользователя
- Удаление пользователя

2. Products Service отвечает за хранение и управление товарами.
Сущность Product содержит:
- id

- price

Поддерживаемые операции:
- Получение списка товаров
- Получение товара по идентификатору
- Создание товара
- Изменение товара
- Удаление товара



3. Orders Service отвечает за хранение и управление заказами.

# Реализация GraphQL Federation
Для объединения микросервисов использовалась технология Apollo Federation. Каждый сервис предоставляет собственную GraphQL-схему и набор резолверов. Для создания подграфов использовался пакет "@apollo/subgraph" - каждый сервис регистрируется как отдельный Subgraph.
Пример подключения схемы:
schema: buildSubgraphSchema({
    typeDefs,
    resolvers
})
Такой подход позволяет независимо разрабатывать и масштабировать отдельные сервисы.



# Реализация API Gateway
Для объединения всех микросервисов был создан отдельный сервис Gateway. Gateway выполняет следующие функции:
- получение схем микросервисов;
- объединение схем в единую GraphQL-схему;
- маршрутизация запросов;
- предоставление единой точки входа для клиента.

Клиент взаимодействует только с Gateway - http://localhost:4000. Gateway самостоятельно определяет, в какой микросервис необходимо направить запрос.



# Реализация CRUD-операций
Для каждой сущности были реализованы операции:
- Create

- Update
- Delete

Поддержка CRUD реализована для всех трех сущностей


# Тестирование системы
После реализации каждого микросервиса было проведено тестирование GraphQL-запросов. Проверялись следующие сценарии:
- Получение списка объектов.
- Получение объекта по идентификатору.
- Создание нового объекта.
- Обновление существующего объекта.
- Удаление объекта.
Тестирование проводилось как напрямую через отдельные микросервисы, так и через Apollo Gateway.
Результаты тестирования показали корректную работу всех запросов и мутаций.

# Особенности реализации
Для хранения данных использовались временные коллекции JavaScript (in-memory storage).
Такой подход был выбран для демонстрации принципов микросервисной архитектуры и работы GraphQL Federation без усложнения проекта подключением внешних баз данных.
При необходимости система может быть расширена путем подключения PostgreSQL, MongoDB или других СУБД без изменения общей архитектуры решения.

## «Инструкция по запуску»
# Предварительные требования
Перед запуском проекта необходимо установить:
- Node.js версии 18 и выше;
- npm

Проверить установку можно командами:
- node -v
- npm -v


# Структура проекта
Проект состоит из четырех независимых компонентов:
├── gateway/
├── users-service/
├── products-service/
└── orders-service/
Каждый компонент имеет собственный файл package.json и запускается как отдельный процесс.

# Установка зависимостей
Необходимо установить зависимости для каждого сервиса.
# Users Service
- cd users-service
- npm install

# Products Service
- cd products-service
- npm install

# Orders Service
- cd orders-service
- npm install

# Gateway
- cd gateway
- npm install

# Запуск приложения
Для работы системы необходимо открыть четыре терминала (для удобства).

# Терминал №1 — Users Service
- cd users-service
- npm start
После запуска сервис будет доступен по адресу: http://localhost:4001

# Терминал №2 — Products Service
- cd products-service
- npm start
После запуска сервис будет доступен по адресу: http://localhost:4002

# Терминал №3 — Orders Service
- cd orders-service
- npm start
После запуска сервис будет доступен по адресу: http://localhost:4003

# Терминал №4 — GraphQL Gateway
После запуска всех микросервисов необходимо запустить Gateway.
- cd gateway
- npm start
Gateway будет доступен по адресу: http://localhost:4000 -  этот адрес является единой точкой входа для клиента.
